kinds:
  agent              An agent: a model with tools and a system prompt, with memory per thread.
  aggregate          Business rules several use cases share (a cart with its totals). Only use cases call it; it may use repositories.
  appConfig          The configuration of the app: its connections (databases, Redis, Kafka, models, vectors).
  appcomponent       The facade of a component: aliases to its use cases.
  config             The configuration of one component: connections only it uses.
  controller         REST routes of the API.
  entity             A table of the project's database.
  graph              A graph of steps: its methods are the nodes.
  listener           A Kafka consumer: `@consumer("topic")` methods receive the messages.
  model              A model: what the API reads and answers, validated.
  repository         The data of one entity: CRUD without writing it and queries built line by line.
  service            Helpers of the use cases: mappings, transformations, calculations without state. Its dependencies are its constructor parameters (injected by type). Only use cases and aggregates call it.
  state              The state of a graph.
  tests              A group of tests (in `test/`).
  tools              Tools for a model: each public method with a doc comment is a tool the model can call.
  usecase            One business operation: a single method `exec` that returns a `Result`.

words:
  abstract           A module that is not instantiated by itself; a module with only signatures is already a `Protocol`.
  get                A property: `get area() double` + block → `@property def area(self) -> float`. Read it as `shape.area`.
  set                The setter of a property: `set area(value: double)` + block → `@area.setter`.
  static             A static method: called on the class (`Math.max(a, b)`), written with `@staticmethod` and without `self`.
